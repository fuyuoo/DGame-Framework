# 领域文档

采用单一上下文布局：

- 根目录 `GLOSSARY.md`：领域术语。
- 根目录 `docs/adr/`：架构决策。

## 阅读规则

探索代码前，读取已有术语表及与当前主题相关的 ADR。
文件不存在时直接继续；由 domain-modeling 在术语或决策确定后按需创建。

若以后出现根目录 `GLOSSARY-MAP.md`，按其中索引读取相关上下文的术语表，并检查对应上下文中的 ADR。

## 使用规则

Issue 标题、设计提案、假设和测试命名使用术语表定义的名称。
发现术语缺口时交给 domain-modeling 处理。
提案与已有 ADR 冲突时，明确指出 ADR 编号、冲突内容及重新讨论的理由。
